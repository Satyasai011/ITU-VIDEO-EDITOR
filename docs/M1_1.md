# M1.1 — Crystal Aurora + Obsidian Precision

This is the M1 premium UI redesign, not M2. Version code 2 / version name `0.1.1-m1.1`. Original project IDs, source URI grants, Room schema version 1, project database name and existing preferences remain compatible. Release builds and hardware verification remain out of scope.

## Implemented

- A compact Crystal Aurora dashboard with ITU Prism identity, restrained cyan/violet surfaces, rounded adaptive project cards and real source thumbnails. New Project and Media Vault lead to existing real functions.
- A grid-first Media Vault with persisted grid/list preference, source/project-name search, recent/name/source-duration sorting, and rotation-aware portrait/landscape filters. Unknown dimensions are excluded only from orientation-specific filters. Multiple project references to one source use the most recently updated project. There is no fake seeded footage.
- Loading/empty/search-empty/library-error states, library retry, individual thumbnail loading/error/retry states. Thumbnail failure does not prevent opening a project.
- Shared `Prism` components: outlined 24dp vectors, accessible labels and selected semantics, 48dp control targets, 56dp primary action/editing buttons, spacing and typography tokens.
- One background MediaMetadataRetriever at a time, scaled frames no larger than 480×360, an LRU bitmap budget of 2–24 MiB depending on available heap, and a disposable 48 MiB JPEG disk cache. Keys include source URI, selected source in-point, duration, dimensions and rotation. Retrievers release in finally blocks; memory cache clears on memory pressure. Generation and disk work run on Dispatchers.IO. No full source copies are created. Frames use closest sync thumbnails; these are not a frame-accurate timeline.
- Obsidian Precision editor with pixel-aspect-aware decoded video fitting, fitted fallback bounds based on source rotation, custom playback/seek/timecodes, accessible IN/OUT trim handles, source information, Save trim, preview trim and the original test export workflow.
- Phone toolbar with bounded, independently scrollable source/trim/export context panels. Tablet windows show collapsible media/inspector panels. Short windows allow scrolling the whole workspace. Content consumes system insets and applies IME padding for import/search keyboards; the header label yields space to its controls at larger font sizes. Resizing out of tablet mode removes side panels immediately, avoiding transitional overlap.
- Approximately 100ms primary press feedback and 220ms panel transitions. Android animator/transition duration settings are observed; zero-duration/reduced-motion settings disable custom transitions. Standard Compose animation timing also follows system duration scaling. Editing callbacks are not queued behind animations.

`ValidationExporter`, encoder capability reporting, the Room entity/DAO/schema and the source import/trim repository implementation remain unchanged except for adding a separate Vault-view preference. Export is still foreground-only 720p H.264/AAC. No frame stepping, split, multitrack, markers, highlights, custom workspace layouts, Shorts or other unfinished operations are exposed.

## Device checklist

1. Upgrade a test installation using the same signing key and confirm existing projects reopen. Fresh GitHub runners can use different debug signing keys: if Android reports an incompatible signature, preserve needed app data before uninstalling the old test build. Uninstall deletes its project database/preferences; source videos remain untouched.
2. On a portrait phone and OnePlus Pad 2 landscape, create a project through SAF, verify its thumbnail, reopen it and play/seek the real source with audio. Repeat for portrait, rotated, anamorphic (if available) and corrupt/missing sources. Check thumbnail retry after restoring readable media.
3. Verify Vault grid/list persistence, search, clear, sorting, both orientation filters and no-results state. Scroll a large collection; monitor memory and repeat entry to exercise cache reads.
4. Adjust both trim handles and Set in/Set out, preview, Save trim, leave/reopen and verify the retained source range. Confirm original media is untouched. Run the [M1 critical media test](DEVICE_VALIDATION.md), including actual MP4 playback and A/V sync.
5. Resize repeatedly between narrow, wide, split-screen and short landscape windows. Verify source/trim/export panels remain reachable, no side panel covers a narrow preview, and export progress/cancel/completion/Open exported MP4 work. Long text and large font scaling need physical inspection.
6. Turn Android animation scales off and on while the app is open. Confirm immediate actions and disabled custom motion when off. Use TalkBack to verify glyph names, selected view state, playback seek and trim-handle adjustment.
7. Run connected instrumentation tests when a device is available. No interrupted export resume or background export is supported.

## Known limits

No automatic media relinking. Thumbnail cache entries cannot detect external edits to the bytes of a source kept at the same URI; failed-thumbnail Retry forces regeneration, and Android may evict the disposable disk cache. Cached images may outlive source access until playback or a regeneration attempt reveals missing media. Metadata is the existing imported M1 metadata, not a scan of the entire device. Motion/layout behavior and preview aspect/rotation must still be inspected on the actual hardware.
